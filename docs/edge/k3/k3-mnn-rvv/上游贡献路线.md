# MNN 上游能贡献什么：5 个方向 + 「有没有人已经在做」

> 2026-10-21 · MNN master `d662ce36` · 查证方式：GitHub API 全量搜索 issue / PR（open + closed）
> 配套：[mnn-rvv-on-k3.md](mnn-rvv-on-k3.md) 是这块板上的实测；本文只谈**往上游做什么**

在 K3 上把 MNN 的两条 RISC-V 路线跑完之后，顺着查了一遍上游：**哪些坑还没人填、哪些已经有人在填、
我们手上的东西够不够提一个 PR**。结论是 5 件可做的事，其中 1 件已经做完并验证，2 件是纯收益的补漏，
1 件是真正吃力的（也是最有价值的）。

| # | 做什么 | 上游有人在做了吗 | 我们这边状态 | 成本 |
| --- | --- | --- | --- | --- |
| 1 | IME2 的 ISA 字符串补 `zfh` / `zihintpause` | **没有**（0 issue / 0 PR） | **补丁写好并在板上验证过** | 已完成 |
| 2 | dispatch 接线回归测试（防「内核是死代码」） | 没有 | 方案已定 | 1~2 天 |
| 3 | IME2 编译冒烟 + 文档修正 | 没有 | 需求明确 | 半天 |
| 4 | **RVV 的 W8/W4 量化 GEMV/GEMM** | **没有**（#4847 只做了 FP32） | 待开工，价值最大 | 1~2 周 |
| 5 | review 三个开放的 RISC-V PR | 在等 review | 我们的实测数据是筹码 | 每篇 1~2 小时 |

## 1. 先查重复：上游现在谁在动 RISC-V

用 GitHub API 把「RISC-V / RVV / IME2 / 量化」相关的 issue 和 PR 全搜了一遍（2026-10-21）：

| 查询 | 命中 | 内容 |
| --- | ---: | --- |
| `is:pr is:open riscv` | 1 | **#4907** 4 字节 raster bitcopy 广播向量化（10-08 起 open） |
| `is:pr is:open IME2` | 2 | **#4865** conv int8 权重求和 kernel；**#4913** packing / depthwise 访存优化 |
| `is:pr is:open quant` | 2 | #4765（QNN 导出，与 RISC-V 无关）、#4865 |
| `is:issue is:open riscv` | **0** | 没有开放的 RISC-V issue |
| `is:pr is:open rvv matmul` | **0** | 量化 matmul 无人做 |
| `is:pr is:closed riscv matmul` | 4 | 含已合入的 **#4847**（E=1 GEMV，**FP32 unpacked**）、被关掉的 **#4957**（TORQ-Tile FP32） |

三条结论：

1. **IME2 默认编不过这件事，上游没人报过**。搜 `IME2` / `march` / `riscv` 的 issue 和 PR 都是空的，
   只有我们这台板子上的错误日志。这是个干净的 bug report + 一行修复。
2. **量化路径没人做**。#4847 已经合入（+186 / −2，7 个文件），但它加的是
   `CPUMatMul` 里 **FP32 非打包** 的 E=1 GEMV；低内存模式（`MNN_LOW_MEMORY=ON`）走的
   **W4 块量化打包权重** 那条路，RVV 下仍然回退标量 C++ —— 也就是本板 5 tok/s 的根因。
3. **开放的 3 个 RISC-V PR 都是零散 kernel**（conv int8 求和、packing/depthwise 访存、bitcopy 广播），
   没有架构性改动，参与 review 的门槛不高。

## 2. 五个方向

### 2.1 【已就绪】IME2 的 ISA 字符串补 `zfh` / `zihintpause`

| 项 | 内容 |
| --- | --- |
| 文件 | `source/backend/cpu/riscv/CMakeLists.txt`（1 行 + 3 行注释） |
| 现象 | `-DMNN_RVV_SPACEMIT_IME2=ON` 直接编译失败，连挂三次：先缺 `zfhmin`、再缺 `zfh`、再缺 `zihintpause` |
| 根因 | IME2 的 kernel 用了标量半精度（`flh` / `fcvt.s.h` / `fmul.h`）和 `pause`，但 CMake 给的 ISA 串只有 `${MNN_RVV_BASE_MARCH}_xsmtvdotii` |
| 修复 | 把 `_zfh_zihintpause` 写进 IME2 目标的 ISA 串，不依赖 `-mcpu` 隐式带入 |
| 影响面 | 只在 `MNN_RVV_SPACEMIT_IME2=ON` 时生效，其它平台零影响 |
| 验证 | 默认配置（只给开关）**10 分 29 秒编完、0 错误**；RVV 测试 4/4；Qwen3-0.6B pp512 / tg128 = **221.28 / 31.23**（与手工传 march 的 225.86 / 31.47 一致） |

现成产物：板子 `~/MNN` 分支 `feature/ime2-march-zfh`，提交 `826bf481`，补丁 `K3:/tmp/mnn-ime2-march.patch`。

```diff
-        set(MNN_SPACEMIT_IME2_MARCH "${MNN_RVV_BASE_MARCH}_xsmtvdotii")
+        # The IME2 sources use scalar half-precision and `pause`: MNNSpacemitIme2GemmI8I4Local.cpp
+        # needs zfh for flh/fcvt.s.h/fmul.h, MNNSpacemitIme2GemmInt8.cpp needs zihintpause.
+        # Declare them here instead of relying on the base string or on -mcpu implying them.
+        set(MNN_SPACEMIT_IME2_MARCH "${MNN_RVV_BASE_MARCH}_zfh_zihintpause_xsmtvdotii")
```

### 2.2 【推荐下一步】dispatch 接线的回归测试

9 月那批 RISC-V PR 复盘时发现一个反复出现的模式：**内核写好了，但 dispatch 没接上，等于死代码**
（#4821 就是「修 depthwise kernel 死代码」）。这类 bug 编译不报、测试也不报，只有跑 benchmark 才会
发现「怎么一点没变快」。

| 项 | 内容 |
| --- | --- |
| 做法 | 在 `test/backend/cpu/RVV*Test.cpp` 里断言：`core->supportRVV` 为真时，关键函数指针 **不等于** 通用实现；再配一个 op 级数值对比 |
| 收益 | 把「性能没变」从人工发现变成 CI 失败 |
| 风险 | 仅测试，零运行时开销 |
| 门槛 | 需要能跑 RVV 的 CI 或 QEMU（MNN 已有 `riscv64` 交叉编译流程） |

### 2.3 【低成本】IME2 的编译冒烟 + 文档修正

现在两处文档都只写「打开开关」：`docs/compile/cmake.md`（选项表）和
`docs/perf/riscv_k3_ime2_asymmetric_w4b64.md`（§3.6 构建命令），没写 ISA 要求 —— 这个 bug 能活到今天，
本质原因就是**没人按文档编过一次**。

- 修文档：补一句 ISA 依赖（修复合入后可以写成「无需额外传 march」）
- 加冒烟：CI 里跑一次 `-DMNN_RVV_SPACEMIT_IME2=ON` 的 configure + build（riscv64 交叉编译器即可，不需要真板）

成本半天，见效快，且和 2.1 是同一个 PR 的自然延伸。

### 2.4 【最大价值】RVV 的 W8 / W4 量化 GEMV/GEMM

这是本板 5 tok/s 的唯一原因（见 [mnn-rvv-on-k3.md](mnn-rvv-on-k3.md) §4.3）：低内存量化路径的主算子
（`MNNPackedMatMul` 系列）没有 RVV 实现，`supportRVV` 为真也照样回退标量。

| 项 | 内容 |
| --- | --- |
| 为什么值得 | 一行 `MNN_USE_RVV=ON` 在 K3 上从 5 tok/s 变 31 tok/s 的空间；对没有 IME2 的板子（VisionFive 2、 Milk-V、K230 等）同样有效 |
| 建议拆法 | ① W8 GEMV（最简单，先证明接线与数值正确）→ ② W4 半字节拆分 + 反量化 → ③ bias/残差与 prefill 的 GEMM 分支 |
| 参考实现 | 仓库里已有的 ARM NEON / x86 AVX 版本（`source/backend/cpu/compute/`），以及 IME2 的 W4B64 结构 |
| 验收门槛 | 多 VLEN（128 / 256 / 512 / 1024）、QEMU 与真机、输出与参考实现一致、AB/BA 多进程测速 |
| 成本 | 1~2 周，可拆 3 个 PR |

### 2.5 【建立信任】review 三个开放的 RISC-V PR

#4907（bitcopy 广播）、#4865（conv int8 权核和）、#4913（packing / depthwise 访存）都在等 review。
我们手上有别人没有的东西：**同一块 K3 板上，标准 RVV 与 IME2 两套构建的端到端数据**，
可以直接回答「这个 kernel 到底省了多少」。参与 review 是成本最低的进场方式。

## 4. 我们的底牌：为什么这些贡献不是空谈

| 数据 | 值 | 来源 |
| --- | ---: | --- |
| 标准 RVV（`MNN_USE_RVV=ON`） | pp512 5.62 / tg128 4.97 | 本板实测 |
| += IME2 | **221.28 / 31.23** | 本板实测（修复后的默认配置） |
| A100 核组（VLEN=1024） | 10.75 / 7.42（p8/tg2） | 同日实测，比 X100 慢约 4 倍 |
| llama.cpp 对照 | 0.8B ≈ 29 t/s；2B Q4_0 pp128 115.7 / tg 13.29 | [k3-report](../k3-report/) |
| 板子内存带宽 | 读 ~20 GB/s、拷贝 ~23 GB/s（标称 52） | [k3-report](../k3-report/) |
| 官方文档 | 381.24 / 54.49（4bit / block 64 / `sym: false` / fp16 scale） | `docs/perf/riscv_k3_ime2_asymmetric_w4b64.md` |

两个能直接写进 PR 描述的事实：

- **标准 RVV 的 5 tok/s 不是配置问题**：`riscv_hwprobe` 实测 V 位为 1，路由正常，是缺内核。
- **IME2 在 A100 上不可用**：A100 确实是 VLEN=1024，但 MNN 在它上面比 X100 慢约 4 倍（p128 那轮
  7 分钟没出结果），所以「1024-bit」这条不能拿来解释官方的 381。

## 5. 复现

```bash
# 1) 复现 IME2 默认配置编不过（master d662ce36）
cmake -S MNN -B build -DCMAKE_BUILD_TYPE=Release -DMNN_USE_RVV=ON -DMNN_RVV_SPACEMIT_IME2=ON
cmake --build build -j8 2>&1 | grep -m3 'unrecognized opcode'

# 2) 应用补丁后重编，应 0 错误
git -C MNN checkout feature/ime2-march-zfh   # 或在你的 fork 上 git am 补丁
cmake -S MNN -B build2 -DCMAKE_BUILD_TYPE=Release -DMNN_USE_RVV=ON -DMNN_RVV_SPACEMIT_IME2=ON
cmake --build build2 -j8

# 3) 端到端数据
./build2/llm_bench -m Qwen3-0.6B-MNN/config.json -t 8 -p 512 -n 128 -rep 3
```
