SpacemiT K3 (RISC-V) 大模型推理实测报告

板子：pingji-k3 · Bianbu 4.0.1 · 16GB · 2026-09-29 · 由远程实测整理

一句话结论
K3 确实能跑 8B，但生成只有 ~2.9 tok/s——因为它是内存带宽瓶颈（CPU 实测 ~20GB/s，不是标称峰值 52GB/s）。 官方调优的小模型才是主力：Qwen3.5-2B 约 13 tok/s；官方"大模型"招牌是 MoE 30B-A3B（只激活 3B，约 12 tok/s）。

坑：ttyd 协议被定制，WebSocket 第一帧必须是认证 JSON {"AuthToken":"","columns":C,"rows":R}，之后才按 '0'+输入 发，否则一敲就断。

3. 内存带宽实测（瓶颈所在）

用自写 microbenchmark（8 路独立累加 + RVV + 巨大页）测 CPU 侧可达带宽：

测法8 线程16 线程
纯读~20 GB/s~20 GB/s
memcpy（读+写）~23 GB/s~23 GB/s
关键点：加核不涨（8→16 线程一样） → 瓶颈是 CPU 复合体到内存的共享端口，不是核心。 LPDDR5 标称峰值 52GB/s 是颗粒峰值，普通 CPU 代码拿不到（典型只有 30–60%），这里约 40%。

8B-Q4 每 token 读 ~5.2GB，理论上限 20GB/s ÷ 5.2GB ≈ 4 t/s，实测 2.9 t/s 已贴近 CPU 能给的极限。

IME 矩阵扩展只加速算力 → prompt 处理快；生成是带宽瓶颈，IME/NPU 都帮不上。

5. 官方「模型动物园」是啥

spacemit-ai-gateway + spacemit-ailab：SpacemiT 给 K3 调好的一批模型 + 网页控制台，覆盖 LLM / VLM / Vision / Speech。模型 GGUF 直接放在 archive.spacemit.com/spacemit-ai/model_zoo/。

官方清单里根本没有 8B 稠密模型。他们"大模型"的招牌是 MoE 30B-A3B——每 token 只激活 3B 参数，只用读 ~2GB，所以又快又大。 ⚠️ 30B-A3B 的 GGUF 约 18GB，16GB 内存塞不下（会疯狂换页）。

6. 硬件视频编解码

板上有硬件 VPU，做 H.264 / H.265 实时编解码（4K），在 ffmpeg 里暴露为 h264_stcodec、h264_v4l2m2m、hevc_v4l2m2m，配套软件 mpp2（SpacemiT Media Processing Platform）。

（注意：/dev/vcs* 是虚拟终端，不是编解码器。）硬件编解码对 NVR/直播/转码很实用，但不稀缺（Pi5、RK3588 都有，RK3588 还支持 8K）。

7. 结论 & 建议

  • 当"便宜 LLM 盒子"不划算：纯推理 CPU 打不过独显；8B ~3 t/s 偏慢。
  • 当 RISC-V AI 开发板很合适：16 核 + IME + NPU + VPU + UCIe + 16GB，是练 RVV/IME kernel、llama.cpp 后端、NPU/ONNX 移植、性能分析的好平台——这些正是 RISC-V 岗位的核心技能。
  • 日常用它聊天：换 Qwen3.5-2B（~13 t/s）或 0.8B（~29 t/s）。
  • 想体验"大模型"：MoE 30B-A3B（需更大内存），或装 spacemit-ailab 跑视觉/语音（NPU 主场）。
