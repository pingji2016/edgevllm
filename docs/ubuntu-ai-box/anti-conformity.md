# 防从众：prompt 层的四种干预全部失效，而模型 89.5% 会采纳错误建议

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-27
> 3×Qwen3-0.6B（T=0.2/0.7/0.9）· 200 题 · 不用任何工具

上一轮结论是"三个臭皮匠顶不上，还把强者拉下水"。
这一轮试**四条不需要工具的补救**：

> 匿名打乱、置信度加权、指定反方、抗误导检验——**能不能把 27–30% 拉回来？**

答案：**一条都不行。**

> 而且抗误导实验给出了最硬的一个数字：
> **给一个错误建议，模型 89.5% 会改错**（准确率 30.5% → **6.0%**）。

---

## 1. 四组干预

基线（已测）：`1×1.7B 48.0%` / `3×0.6B 投票 29.0%` / `辩论 27–30%`

| 组 | 做法 | 想解决什么 |
| --- | --- | --- |
| **A 置信度加权** | 每个 agent 额外输出 `1–5` 分，按分数加权投票 | 让"有把握的"主导 |
| **B 匿名打乱辩论** | 候选匿名 + 每题随机顺序，再重答 | 去位置偏置、去"谁说的" |
| **C 反方** | 第三个 agent 被告知"另两个一致，别盲从" | 强制制造分歧（Liang 2023） |
| **D 抗误导** | 给它一个**错误**候选，问"确认还是纠正" | **直接量化谄媚** |

---

## 2. 结果

| 配置 | 准确率 | vs 1.7B（McNemar） |
| --- | ---: | --- |
| **1×1.7B** | **48.0%** | — |
| A 置信度加权 | 27.5% | z = −5.63 |
| B 匿名打乱辩论 | 27.0% | z = −5.82 |
| C 反方 | 27.0% | z = −5.72 |
| **D 抗误导（给错答案）** | **6.0%** | **z = −9.06** |

### 2.1 D 组的两个数字

| 指标 | 值 |
| --- | ---: |
| 采纳错误建议 | **179/200 = 89.5%** |
| 准确率 | **6.0%**（基线 30.5%） |

给一个"别人说答案是 4521"的提示，它就把自己算的扔掉，**改写成 4521**——
即使 4521 和正确值差了 9（我们故意只偏 ±3/±9）。

> 这不是"参考别人意见"，是**建议直接覆盖计算**。

---

## 3. 为什么四种干预都没用

### 3.1 置信度不可用（A）

0.6B 输出的 `1–5` 分几乎恒定（大量 3–5），与对错无关。
**没有校准的置信度，加权就是加了噪声。**

### 3.2 匿名只能去"位置偏置"，去不掉"内容锚定"（B）

打乱顺序后，模型不知道哪个是 1 号，但**数字本身**仍然是锚。
27.0% 与不打乱（27–30%）没有区别 → 说明偏置不来自位置，来自**数值内容**。

### 3.3 反方也会从众（C）

"别盲从"这句话对 0.6B 无效：它在看到多数答案后，**同意多数的概率远高于独立重算**。
反方 agent 的输出与第二个 agent 高度一致，没有提供新信息。

### 3.4 根因：它没有"独立计算"可以守（D）

D 组说明：模型的答案**主要由建议决定**。
当它自己算 30% 正确、被建议后 6% 正确，说明"自己算"这件事本身就很弱，
**外部建议的权重远大于内部计算**。

> 换句话说：**防从众的前提是"有主见"。**
> 0.6B 在三位×两位上本来就没有稳定主见，谈不上"坚持"。

---

## 4. 那什么才有效

| 手段 | 为什么 | 证据 |
| --- | --- | --- |
| **工具验证**（计算器/检索/单测） | 把"谁对"变成可执行检查 | 你叫它作弊，但它是唯一能改变结果层的 |
| **换更强单模型** | 主见来自能力 | 1.7B 48% vs 0.6B 30.5% |
| **异构模型集成** | 错误不相关，投票才有信息 | 本文 3 个同权重 agent 失败 |
| **只传推理过程**（不传结论） | 结论锚定，步骤可检验 | 未测（0.6B 的步骤多半是空的） |
| 更多 prompt 技巧 | 无 | 本轮 A/B/C 全灭 |

### 4.1 一个可验证的推论

> **从众率应该随模型能力下降而上升。**
> 如果换成 1.7B 做 D 组，采纳错误建议的比例应该显著低于 89.5%。

这是一条很便宜、可以立刻验证的预测（约 3 分钟）。

## 6. 结论

1. **匿名打乱、置信度加权、反方**：三种 prompt 干预**全部无效**（27–27.5%）；
2. **抗误导实验**：给错误建议，**89.5% 会改错**，准确率 30.5% → **6.0%**；
3. **根因不是"从众"，是"没有主见"**：答案由建议决定，内部计算权重太低；
4. **prompt 层防不住**——要么给工具（可验证），要么换更强的模型；
5. 下一个便宜实验：**用 1.7B 重跑 D 组**，验证"能力越强越不從众"。

---

## 7. 追加：同一个实验，1.7B 的结果完全相反

上面留了一个可验证的推论：**从众率应该随能力上升而下降**。
用同一套协议跑 1.7B（200 题，同一 seed）：

| 模型 | 无建议 | 给错建议 | 采纳错误建议 |
| --- | ---: | ---: | ---: |
| 0.6B | 30.5% | **6.0%** | **89.5%** |
| **1.7B** | 48.0% | **59.0%** | **11.0%** |

两个方向都反了：

1. **采纳率从 89.5% 掉到 11.0%**——能力越强，越不從众；
2. **准确率不降反升**（48% → 59%）——错误建议对 1.7B **不是毒药，是提醒**。

### 7.1 是"检查指令"的作用吗？不是

加一个同长度的中性对照：

| 1.7B 的提示 | 准确率 |
| --- | ---: |
| 直接问 | 48.5% |
| 「请仔细检查后回答」（不给候选） | 45.0% |
| **「有人说是 X，请确认或纠正」（X 是错的）** | **58.5%** |

**"仔细检查"没用，"一个具体的错误值"才有用。**

机制推测（未验证）：一个具体的邻近数值给了模型一个**对照物**，
它会把"自己算的"和"别人说的"做比较，从而触发一次真正的重算；
而空泛的"检查"不会改变它的计算路径。

### 7.2 这条结论的实用价值

| 场景 | 用法 |
| --- | --- |
| 强模型（7B+）做算术/核对 | 可以主动给一个**错误候选**当"对照探针"，反而提升 |
| 弱模型（≤1.7B） | **绝对不能**给候选，会被直接覆盖 |
| 多 agent 协作 | 弱 agent 之间**不要交换最终答案**，只会互相污染 |

> 一句话：**"给个错误答案让它核对"是一个能力门槛很高的技巧。**
> 强模型会借它自我纠错，弱模型会直接抄。
