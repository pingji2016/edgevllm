# 三个臭皮匠，顶不了一个诸葛亮（还可能把他拉下水）

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-27
> 任务：三位×两位（200 题，seed 999）· 5 种配置 · 全部实测

问题一句话：

> **3 个 0.6B agent 协作，能不能顶 1 个 1.7B？**

答案：**不能，而且差距很大。**

> 3×0.6B 投票 **29%**、辩论 **27–30%**、MoA **30.5%**；
> 1×1.7B 单独答 **48%**。
> **更糟的是：把 3 个小模型的答案喂给 1.7B 汇总，反而比它自己答低 17 pp。**

---

## 1. 设置

| 项 | 值 |
| --- | --- |
| 任务 | 三位数 × 两位数，200 题 |
| 小模型 | Qwen3-0.6B × 3，**同权重**，只改 temperature/seed |
| 大模型 | Qwen3-1.7B |
| 温度 | A=0.2（精确）、B=0.7（发散）、C=0.9（审查） |
| 步数 | 6 步（与之前 agent 实验一致） |

### 1.1 五种配置

| # | 配置 | 协议 |
| --- | --- | --- |
| 1 | **1×1.7B** | 贪心，单独作答 |
| 2 | 3×0.6B 投票 | 三个独立答，取多数 |
| 3 | 3×0.6B 辩论 1 轮 | 看到另外两个的答案后重答，再投票 |
| 4 | 3×0.6B 辩论 2 轮 | 再来一轮 |
| 5 | **MoA** | 3 个 0.6B 给候选，1.7B 判断并作答 |

---

## 2. 结果

| 配置 | 准确率 | vs 1.7B（McNemar） |
| --- | ---: | --- |
| **1×1.7B** | **48.0%** | — |
| 3×0.6B 投票 | 29.0% | 只有它对 5 / 只有 1.7B 对 43，**z = −5.48** |
| 3×0.6B 辩论 1 轮 | 30.0% | 6 / 42，**z = −5.20** |
| 3×0.6B 辩论 2 轮 | 27.0% | 4 / 46，**z = −5.94** |
| **MoA（3×0.6B + 1.7B）** | **30.5%** | 6 / 41，**z = −5.11** |

（对照：单个 0.6B 贪心是 **30.5%**——也就是说 **3 个 0.6B ≈ 1 个 0.6B**。）

---

## 3. 三个结论

### 3.1 协作没有产生任何增益

单个 0.6B 已经 30.5%，三个 0.6B：
- 投票 29.0%（**−1.5 pp**）
- 辩论 1 轮 30.0%（−0.5 pp）
- 辩论 2 轮 27.0%（**−3.5 pp**）

**多两个 agent，准确率不动，成本 ×3。**

### 3.2 辩论越辩越差

两轮辩论比一轮更低（30.0% → 27.0%）。原因是**锚定与从众**：
看到别人写 4521，它倾向于跟着改，即使自己原来的 4530 更接近。

> 这和 `test-time-scaling.md` 的结论同源：错误是**系统性**的，
> 多个同权重 agent 会犯**同一个错**，互相确认只会加强错误。

### 3.3 MoA 把强者拉下水（最反直觉）

| 配置 | 准确率 |
| --- | ---: |
| 1.7B 自己答 | **48.0%** |
| 1.7B 看 3 个 0.6B 的候选后答 | **30.5%** |

**给它三个错误候选，它反而不会做了。** 这 17 pp 的下降说明：
聚合器的判断力被错误的候选**锚定**了——它倾向于在给定选项里选一个，
而不是坚持自己算。

> 这是"三个臭皮匠"最危险的形态：**不是没帮忙，是帮倒忙。**

---

## 4. 为什么失败：三个必要条件都没满足

多 agent 协作要成立，至少需要一条：

| 条件 | 本例是否满足 | 说明 |
| --- | --- | --- |
| **错误不相关** | ❌ | 三个 agent 同一份权重，错的地方高度重合 |
| **能引入新信息** | ❌ | 只交换最终答案，没有新的计算/检索 |
| **有外部验证** | ❌ | 没有计算器、没有标准答案可查 |

文献里 debate / MoA 的增益，通常来自：
- **异构模型**（GPT-4 + Claude + Llama，错法不同）；
- **带推理过程**（批评能指出具体步骤错在哪）；
- **有工具/验证器**（算完能验算）。

我们三条都不满足。

## 5. 成本

| 配置 | 生成次数 | 相对成本 |
| --- | ---: | ---: |
| 1×1.7B | 200 | 1× |
| 3×0.6B 投票 | 600 | **3×** |
| 3×0.6B 辩论 2 轮 | 1,800 | **9×** |
| MoA | 800（600 小 + 200 大） | 4× |

**花 3–9 倍算力，拿到 60% 的准确率。**

---

## 6. 那什么时候"三个臭皮匠"真的有用

| 场景 | 为什么可能有用 |
| --- | --- |
| **异构模型**（不同厂商/不同训练数据） | 错误不相关，投票/辩论才有信息量 |
| **角色分工**（一个查、一个算、一个写） | 引入新信息，而不是重复同一判断 |
| **有验证器**（单测、计算器、检索） | 能把"批评"变成可执行检查 |
| **长链路任务**（写代码、做调研） | 单步错误可被后续步骤发现 |

反例（本例）：**同一模型、同一任务、只交换答案**——这是最弱的一种协作，
也是最容易被误以为"多 agent 有用"的一种。

## 7. 复现

```bash
cd ~/apps/minimind
python multi_agent.py    # 5 配置 × 200 题，约 1 分钟
# 产物：multi_agent.json（含逐题对错）
```

### 7.1 实现细节

- 三个 agent 共享一份 0.6B 权重（1.2 GB），不同 temperature/seed；
- 1.7B 与 0.6B 同时驻留，共约 4.6 GB；
- 全部 200 题跑完 **58 秒**（含模型加载后的推理）。

---

## 8. 结论

1. **3×0.6B ≈ 1×0.6B**（29–30% vs 30.5%），协作零增益；
2. **辩论越辩越差**（2 轮 27%），因为同权重 agent 的错误是相关的；
3. **MoA 把强者拉下水**：1.7B 看三个错误候选后从 48% 掉到 30.5%；
4. **多 agent 的前提是"错误不相关 + 引入新信息 + 可验证"**，
   同模型投票一条都不满足；
5. **要提升就换更强的单模型，或者给它工具**——不是给它更多同伴。
