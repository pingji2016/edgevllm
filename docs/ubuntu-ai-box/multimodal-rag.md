# 多模态 RAG：用中文搜图，原版 CLIP 会崩

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-27
> 24 张受控图 · 原版 CLIP vs Chinese-CLIP · 12 条中英文查询

前面所有 RAG 都是"文字搜文字"。这一轮试**文字搜图**，问题很直接：

> **中文写一句"红色的圆形"，能不能把那张图找出来？**

答案取决于用哪个模型：

> 同一个原版 CLIP，**英文 92%，中文只有 17%**。
> 换 Chinese-CLIP 后中文回到 **75%**。

---

## 1. 设置

| 项 | 值 |
| --- | --- |
| 图片 | **24 张**受控合成图：6 色 × 4 形状（圆/方/三角/星） |
| 查询 | 12 条中文 + 12 条同义英文 |
| 指标 | R@1（top-1 是否就是目标图） |
| 模型 A | `openai/clip-vit-base-patch32`（英文训练） |
| 模型 B | `OFA-Sys/chinese-clip-vit-base-patch16`（中文训练） |
| 引擎 | transformers 5.x，float32，GPU |

> 用合成图是为了**可复核**：每张图只有"颜色 + 形状"两个属性，
> 错了能立刻判断错在哪。真实图片没有干净的 ground truth。

---

## 2. 结果

| 模型 | 查询语言 | R@1 |
| --- | --- | ---: |
| 原版 CLIP | 英文 | **92%（11/12）** |
| 原版 CLIP | 中文 | **17%（2/12）** |
| Chinese-CLIP | 中文 | **75%（9/12）** |

### 2.1 这不是"小幅退化"，是语言不通

同一批图片、同一个模型，只换查询语言，R@1 从 92% 掉到 17%。
原因不是"中文歧义"，而是**原版 CLIP 的分词器/TEXT 编码器基本没训过中文**：
"红色的圆形" 在它眼里接近一串无意义 token。

> 这条对本地系统很关键：**以文搜图的中文能力，不能从"CLIP 很强"外推。**

### 2.2 Chinese-CLIP 也只到 75%

24 张图里错 3 张。从任务性质看，错的更可能是**属性绑定**
（选对了形状但颜色错，或反之）——这类"颜色 × 形状"的组合正是
对比学习最容易学混的地方。
（本轮未逐条记录错误样例，此句为推测。）

---

## 3. 成本

| 环节 | 耗时 | 说明 |
| --- | ---: | --- |
| 图像编码（24 张） | ~0.7 s | **约 30 ms/张**，可离线建索引 |
| 文本编码（1 条） | ~25 ms | 在线查询 |
| 相似度检索 | <1 ms | 24 条向量，矩阵乘即可 |

图像编码是一次性成本；线上只有"编码查询 + 点积"，和文本 RAG 一样便宜。

---

## 4. 落地建议

| # | 建议 | 依据 |
| ---: | --- | --- |
| 1 | **中文场景必须用 Chinese-CLIP**（或更大的中文多模态模型） | 原版中文 17% vs 中文版 75% |
| 2 | **图和文分两个索引**，不要混在一个向量空间 | 两个模型的空间不通用 |
| 3 | **图像编码离线做**，线上只编码查询 | 30 ms/张 不适合实时 |
| 4 | 属性检索（颜色+形状+位置）要做**组合校验**，别只信 top-1 | 75% 已经是受控任务的上限附近 |

### 4.1 什么时候值得上多模态 RAG

| 场景 | 是否值得 |
| --- | --- |
| 截图/相册里找图（"找那张红色的架构图"） | ✅ 值得，但要用中文模型 |
| 文档里的图表检索 | ⚠️ 图表信息密度高，CLIP 容易丢细节 |
| OCR 类需求（读图里的字） | ❌ 用 OCR（`deepseek-ocr.md`），不是 CLIP |

## 5. 复现

```bash
cd ~/apps/minimind
python mm_rag.py     # 生成 24 张图 + 三个模型/语言组合
# 产物：mm_rag.json，图片在 /tmp/mm_rag/
```

### 5.1 踩坑记录（值得记）

1. **processor 必须传 PIL 图像**，传文件路径会静默出错（第一次跑出 0%）；
2. **`get_*_features` 在 transformers 5.x 返回结构体**，取 `pooler_output`；
3. **不要二次投影**：返回的已经是投影后向量，再乘一次 `text_projection`（512→512）
   会把文本特征彻底破坏——这是第二个 0% 的来源。

> 三个 bug 的共同点：**没有断言中间张量的形状/范数**。
> 如果一开始就打印 `feat.shape` 和 `norm`，五分钟就能定位。

---

## 6. 结论

1. **原版 CLIP 的中文以文搜图不可用**（17%），英文 92%；
2. **Chinese-CLIP 中文 75%**，可以做，但属性组合仍是短板；
3. **成本很低**：图像 30 ms/张（离线），查询 25 ms；
4. **多模态 RAG 的第一道选择题是"语言模型选对了吗"**，不是向量库或切片。
