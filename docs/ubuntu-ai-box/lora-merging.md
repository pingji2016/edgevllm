# LoRA 合并：同任务的两个适配器，合并不出增益

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-27
> Qwen3-1.7B · GRPO LoRA（60%）+ RFT LoRA（52%）· 同一套 200 题

问题：

> **两个在同一任务上训出来的 LoRA，加权合并能不能超过最好的那一个？**

答案：**不能，严格落在两个端点之间。**

---

## 1. 设置

| 项 | 值 |
| --- | --- |
| 基座 | Qwen3-1.7B（bf16） |
| LoRA A | GRPO 300 步（实测 60.0%） |
| LoRA B | RFT 拒绝采样微调（实测 52.0%） |
| 合并方式 | 线性插值：`θ = α·A + (1−α)·B`，逐参数平均 |
| 可合并参数 | 392 个张量（r=16，7 个投影层） |
| 评测 | 同一 200 题（seed 999），贪心 |

---

## 2. 结果

| α（GRPO 权重） | 精确 | 误差<1% |
| ---: | ---: | ---: |
| **1.00（纯 GRPO）** | **60.0%** | **98.5%** |
| 0.75 | 57.5% | 96.5% |
| 0.50 | 56.0% | 93.0% |
| 0.25 | 54.0% | 92.0% |
| 0.00（纯 RFT） | 52.0% | 89.5% |

### 2.1 三个读数

1. **严格单调**：α 从 1 降到 0，准确率从 60% 单调降到 52%，没有中间峰值；
2. **没有协同**：任何混合都比纯 GRPO 差；
3. **也没有灾难性干扰**：0.5 时是 56%，正好在两端点之间（不是崩到 30%）。

> 线性合并在这里就是**插值**，不是"取长补短"。

---

## 3. 为什么

两个适配器**学的是同一个任务**：

- GRPO 学到的是"压低错误答案、微调末位"；
- RFT 学到的是"复制正确分布"。

它们的参数更新方向高度相关（都在同一批题型上），
所以加权平均只是**在两个解之间走直线**，而这条直线上的点不会比端点更好。

**合并真正有用的场景是"不同能力"**：

| 场景 | 合并是否有意义 |
| --- | --- |
| 同任务两次训练（本例） | ❌ 只是插值 |
| 一个会数学、一个会写作 | ✅ 可能兼得 |
| 一个懂中文、一个懂代码 | ✅ 常见做法 |
| 全参与 LoRA 合并 | ⚠️ 尺度差异大，常需 TIES/DARE |

### 3.1 为什么没试 TIES

TIES / DARE 针对的是"多个全参微调模型冲突"：
先剪掉小幅参数、再按符号投票。这里两个 LoRA 的更新方向基本一致，
**冲突很少**，TIES 预计也不会带来增益。若要验证，下一步可以补。

差 0.5 pp，说明这条评测链是稳定的（比之前那个 3.5 pp 的批量/逐条差异小，

---

## 6. 结论

1. **同任务的两个 LoRA 合并没有增益**（60% 仍是最好）；
2. **合并结果严格单调**，说明它只是插值，不是能力叠加；
3. **要合并，就合并不同能力**；同任务的收益应该来自"训得更好"，不是"混两个"；
4. 本例也证明了**没有灾难性干扰**——混合不会崩，只是不赚。
