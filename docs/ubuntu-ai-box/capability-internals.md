## 一、Wav2Lip：让照片开口说话

### 1.1 它解决的是什么问题

输入 **一张脸（或一段视频）+ 一段音频**，输出**口型与音频逐帧同步**的视频。
难点在于"同步"是**跨模态**的（听与看的对应关系），不是简单的图像变换——
这也是为什么它的核心贡献不是生成网络，而是**一个会判断"口型对不对"的判别器**。

论文标题把结论写在脸上：*A Lip Sync Expert Is All You Need*。

### 1.2 架构：三块拼起来

```
                 ┌──────────────────────┐
   音频 wav ───▶ │ 提取 mel 频谱 80×16  │
                 └──────────┬───────────┘
                            ▼
                   ┌────────────────┐
                   │ 音频编码器     │  6 层 conv + BN，stride 2
                   │ (VGG 风格)     │  输出 512 维
                   └────────┬───────┘
                            │ reshape 成 1×1×512 → 平铺到 12×12
                            ▼
   ┌───────────────────────────────────────────┐
   │ 视觉编码器 (6 层 conv, 输入 6 通道)        │  输出 512×12×12
   │  通道 0-2：被遮挡的下半脸（目标区域涂黑）  │
   │  通道 3-5：参考帧（完整脸）               │
   └────────────────────┬──────────────────────┘
                        │ concat(视觉特征, 音频特征)
                        ▼
              ┌──────────────────────┐
              │ 解码器：转置卷积上采样 │  512→256→128→64→3
              └──────────┬───────────┘
                         ▼
                  96×96×3 的下半脸
                         │ 按 bounding box 贴回原图
                         ▼
                     输出视频帧
```

三个关键设计：

1. **输入 6 通道**：把"要被替换的区域涂黑"和"原图"一起喂进去，
   网络才知道"哪里要生成、周围长什么样"。
2. **只生成 96×96 的下半脸**，再贴回原图。这是 2020 年的算力妥协，
   但也带来好处：输出分辨率与生成质量解耦。
3. **音频特征被"平铺"成空间维度**（1×1 → 12×12），靠 concat 与视觉特征融合，
   而不是 cross-attention——结构极简，所以推理快（本机 3.48 s 音频只要 9.06 s）。

### 1.3 为什么"同步"能学会：SyncNet 判别器

生成网络可以学会"画一个像嘴的东西"，但很难自己学会"这个口型对应这个音素"。
所以训练时挂一个**预训练好的 SyncNet** 当裁判：

```
        人脸帧序列            mel 频谱片段
             │                     │
             ▼                     ▼
      视觉编码器              音频编码器
             │                     │
             └──────► 各自 512 维 ◄─┘
                        │
                        ▼
              余弦相似度 → 是否同步
```

损失由三部分组成：

```
L = L1(生成帧, 真值帧)                    ← 像素要像
  + λ_sync · L_sync(生成帧, 音频)         ← 口型要对（SyncNet 打分）
  + λ_gan  · L_adv                        ← 只有 wav2lip_gan 有（更清晰但更抖）
```

`λ_sync` 是关键超参：给太小学不会口型，给太大画质崩。

### 1.4 本机实测时的两个工程细节

| 问题 | 现象 | 根因 | 解法 |
| --- | --- | --- | --- |
| `s3fd.pth` 残缺（5.4 MB / 应 86 MB） | `RuntimeError: unexpected EOF` | 下载站给了截断文件 | **`--box 0 512 0 512` 直接给框，完全不加载 s3fd** |
| `--static` 仍报同样错误 | 以为 static 能跳过检测 | 源码里 static 只是"只检测首帧拿裁剪框"，**仍会调用检测器** | 同上：`--box` 才是真跳过 |

```python
# inference.py 的真实逻辑（简化）
if args.box[0] == -1:
    if not args.static:
        face_det_results = face_detect(frames)      # 每帧都检测
    else:
        face_det_results = face_detect([frames[0]]) # ← 仍是检测！只是只做一次
else:
    face_det_results = [[f[y1:y2, x1:x2], (y1,y2,x1,x2)] for f in frames]  # ← 用给定框
```

**本机数据**：3.48 s 音频 → 9.06 s 处理（0.38× 实时），输出 512×512 / 25 fps / 84 帧。

### 1.5 能力边界

- 只改嘴，**不改表情、不转头**；输入脸最好正对镜头、嘴部清晰
- 侧脸、遮挡、大角度会明显劣化（训练数据以正面为主）
- 96×96 的内部分辨率意味着**放大后嘴部细节有限**
- 伦理：仓库里只用程序化合成脸，不用真人素材

## 二、InsightFace（buffalo_l）：人脸识别是怎么做到"跨图认人"的

### 2.1 它解决的是什么问题

给定任意两张图，判断"是不是同一个人"。
核心不是分类（分类要固定人数），而是把脸映射成**一个向量**，让"同人向量近、异人向量远"。

### 2.2 buffalo_l 是一个模型包，不是单个模型

| 子模型 | 文件 | 作用 | 输出 |
| --- | --- | --- | --- |
| 检测 + 5 点关键点 | `det_10g.onnx` (17 MB) | RetinaFace 变体，找脸在哪 | bbox + 5 landmarks |
| 识别（身份特征） | `w600k_r50.onnx` (167 MB) | **ArcFace**，ResNet50 骨干 | **512 维 embedding** |
| 2D 106 点 | `2d106det.onnx` (4.8 MB) | 精细关键点 | 106 点 |
| 3D 68 点 | `1k3d68.onnx` (137 MB) | 3D 形变模型参数 | 3D 68 点 |
| 性别年龄 | `genderage.onnx` (1.3 MB) | 属性估计 | 性别/年龄 |

识别链路（我们实际用的部分）：

```
输入图
  │
  ▼ RetinaFace 检测
bbox + 5 个关键点（双眼、鼻尖、双嘴角）
  │
  ▼ 相似变换（similarity transform）
把脸旋转/缩放/平移对齐到 112×112 的固定模板
  │   ← 这一步至关重要：不对齐，后面的 embedding 会大幅劣化
  ▼ ResNet50 + ArcFace
512 维向量 → L2 归一化
  │
  ▼ 余弦相似度
cos(a,b) ∈ [-1, 1]
```

### 2.3 原理核心：ArcFace 的加性角度间隔

普通 softmax 分类只要求"分对"，会把同类特征压在一个很宽的区域里。
ArcFace 在**角度**上加一个间隔 m，把类内收紧、类间推开：

```
          e^{s·cos(θ_yi + m)}
L = -log ─────────────────────────────────────
          e^{s·cos(θ_yi + m)} + Σ_{j≠yi} e^{s·cos θ_j}
```

- `θ_yi`：样本与**真实类别**权重向量的夹角
- `m`（常见 0.5 rad ≈ 28.6°）：人为制造"更难"的分类任务
- `s`（常见 64）：缩放因子，控制 logits 范围

**几何直观**：模型必须把同类样本压进一个 m 宽的"楔形"区域才能分对，
于是同一人的所有脸被挤到一起，不同人被推得更远。这就是为什么 512 维向量
直接做余弦相似度就够用，不需要再训分类器。

### 2.4 怎么用：阈值

| 场景 | 常用阈值（余弦） |
| --- | --- |
| 1:1 验证（是不是同一个人） | ≈ 0.5 |
| 1:N 检索 / 聚类 | 0.6 – 0.7（宁严勿松） |

**本机实测**：

- 模型加载 1.6 s；CPU 推理 70–500 ms/张（取决于检出人脸数）
- 两张不同的生成图里同一个角色 → 相似度 **1.00**
- 程序化合成的"画出来的脸"检不出（检测器依赖真实图像统计）

### 2.5 能力边界

- 大角度侧脸、强遮挡、低分辨率会掉点
- 跨年龄、跨种族有偏差（训练集以西方人脸为主时更明显）
- **embedding 是生物特征**，落盘需谨慎（不是"匿名数据"）

## 三、SDXL + LoRA：16 GB 显存上做扩散模型微调

### 3.1 SDXL 的组成

```
提示词 ──┬─▶ CLIP ViT-L   (768 维)  ─┐
         └─▶ OpenCLIP bigG (1280 维)─┴─▶ concat = 2048 维 文本条件
                                                      │
噪声 latent z_t (128×128×4，对应 1024² 图像) ─────────┤
                                                      ▼
                                          ┌────────────────────┐
   微条件：原图尺寸 / 裁剪坐标 ──────────▶│  UNet (≈2.6 B)      │
                                          │  cross-attn 注入文本 │
                                          └─────────┬──────────┘
                                                    ▼
                                          预测噪声 ε_θ
                                                    │
                                          VAE decoder │
                                                    ▼
                                                 图像
```

三个容易被忽略的细节：

1. **两个文本编码器**：一个擅长细节（CLIP-L），一个语义更强（bigG），拼起来是 2048 维。
2. **微条件（micro-conditioning）**：SDXL 把"训练时这张图的原始分辨率/裁剪位置"也当输入，
   否则出图会出现"构图崩坏"。对应代码里的 `added_cond_kwargs={"text_embeds":..., "time_ids":...}`。
3. **latent 空间**：1024² 图 → 128×128×4 的 latent，训练/采样都在 latent 上做，省 48 倍算力。

### 3.2 扩散的训练目标（一行公式）

前向加噪：`z_t = √(ᾱ_t)·z_0 + √(1-ᾱ_t)·ε`

训练就是让网络从 `z_t` 和 `t` 反推 `ε`：

```
L = E[ ‖ ε − ε_θ(z_t, t, c) ‖² ]        c = 文本 + 微条件
```

出图时反着走（DDIM / Euler），并用 **CFG** 放大条件信号：

```
ε = ε_θ(z_t, c_空) + w·(ε_θ(z_t, c) − ε_θ(z_t, c_空))
```

`w`（guidance_scale）越大越贴提示词，但过大就过饱和/崩图。

### 3.3 LoRA 为什么能只训 0.45% 的参数

全参微调要改 2.6 B 个权重；LoRA 假设**微调的"变化量"是低秩的**：

```
W' = W + ΔW,   ΔW = B·A
A ∈ R^{r×k},  B ∈ R^{d×r},  r ≪ min(d,k)
```

- 前向：`h = Wx + (α/r)·B(Ax)`
- 初始化：`A` 随机、`B` 全零 → 训练开始时 `ΔW = 0`，**不破坏原模型**
- 我们用的 `r=8`，挂在 UNet 的 `to_q / to_k / to_v / to_out.0` 上 →
  **11.61 M 可训练参数**（占 2.6 B 的 0.45%）

为什么这样还能学到东西：低秩假设意味着"你想要的风格/主体"落在少数几个方向上，
用几百张图把它对齐进这 8 维子空间就够了。代价是**容量有限**——学不了大改结构的东西。

### 3.4 16 GB 显存怎么塞下 SDXL 训练

SDXL 训练的三座大山：UNet 权重（~5 GB）、VAE、文本编码器，加上反向传播的激活。

我们用的三招（也是本机能跑通的原因）：

| 手段 | 作用 | 本机收益 |
| --- | --- | --- |
| **预计算 latent** | VAE 只在开头跑一次，之后全用 latent | 释放 VAE（~0.3 GB）与每步解码开销 |
| **预计算文本 embedding** | 两个文本编码器只跑一次 | 释放 ~1.5 GB，每步省两次前向 |
| **梯度检查点** | 反向时重算激活而不保存 | 激活显存从 O(层数) 降到 O(1) |

实测显存峰值 **7,009 MiB**（此时还有一个 6.4 GB 的常驻服务在跑）。

### 3.5 本机实测数据

| 项 | 数值 |
| --- | ---: |
| LoRA 可训练参数 | 11.61 M（r=8） |
| 单步耗时（512², batch 1） | **676 ms** |
| **300 步总时长** | **约 3.4 分钟** |
| 显存峰值 | 7,009 MiB |
| 单文件管线加载 | 140–160 s |
| 加载 LoRA 出图（768², 12 步） | 3.2 s，峰值 7,987 MiB |

> 结论：这张卡上 **"LoRA 微调"不是"勉强能跑"，而是"几分钟一轮"**——
> 与"全参微调 8B LLM"完全是两个量级的事情，不要在心理上混为一谈。

### 3.6 两个踩坑

1. **HF 缓存里的 `stabilityai/stable-diffusion-xl-base-1.0` 是残缺的**（44 KB，权重从未下全），
   `from_pretrained` 必然失败。改用 ComfyUI 里的单文件 `sd_xl_base_1.0.safetensors` +
   `from_single_file`。
2. **`save_attn_procs()` 已废弃**（只支持 Custom Diffusion），要用 `save_lora_adapter()`。

## 四、三项横向对比：它们各自动的是哪一层

| | Wav2Lip | InsightFace | SDXL-LoRA |
| --- | --- | --- | --- |
| 任务 | 音频→口型 | 图像→身份向量 | 提示词→图像（微调） |
| 核心机制 | SyncNet 判别同步 | ArcFace 角度间隔 | 低秩适配 + 扩散 |
| 网络规模 | ~30 M | ResNet50 (25 M) + 检测器 | UNet 2.6 B（LoRA 11.6 M） |
| 本机耗时 | 9.06 s / 3.5 s 音频 | 0.07–0.5 s/张 | 训练 0.68 s/步 |
| 显存 | < 2 GB | < 1 GB（CPU 也能跑） | 7 GB |
| 关键约束 | 脸要正、要清晰 | 要对齐到 112×112 | 低秩 → 学不了大改结构 |

**共同点**：三者都把"难的部分"交给了**一个预训练的判别/度量模块**
（SyncNet、ArcFace、文本编码器），主网络只学"往哪个方向改"。
这是端侧 AI 应用最典型的工程范式——**大模型负责判断，小模型负责生成**。
