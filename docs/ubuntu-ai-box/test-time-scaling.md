# 测试时扩展 vs 训练时扩展：投票救不了系统性错误

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-26
> 承接 `rlvr-small-model.md`：昨天 RL 用 20 分钟把 47% → 60%

一个很实际的问题：

> **不训练，只多采样几次投票，能不能顶得上 RL？**

结论：**在这个任务上完全不行**（+0 pp），原因很清楚——

> **模型的错误是系统性的，不是随机的。** 同一个问题问 32 次，
> 它 88% 的时间给同一个错误答案，投票只是在重复这个错误。

---

## 1. 实验设置

| 项 | 值 |
| --- | --- |
| 任务 | 三位数 × 两位数（与昨天 RL 同题） |
| 题量 | 200 道固定题（seed 20250101） |
| 采样 | 每题 32 个答案，T=0.8 / top_p=0.95 |
| 评估 | 取前 N=1/2/4/8/16/32 个做多数投票 |
| 模型 | ① 基座 Qwen3-1.7B ② 基座 + 昨天 GRPO 的 LoRA |
| 附加指标 | `oracle@N`：N 个答案里**只要有一个对**就算对（上界） |

---

## 2. 结果

| N | 基座 投票 | 基座 oracle | LoRA 投票 | LoRA oracle |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 48.0% | 48.0% | 55.0% | 55.0% |
| 2 | 48.0% | 49.0% | 55.0% | 60.0% |
| 4 | 48.5% | 49.5% | 55.0% | 63.5% |
| 8 | 47.0% | 49.5% | 56.0% | 67.5% |
| 16 | 47.5% | 50.5% | 56.5% | 68.0% |
| 32 | **47.0%** | 51.0% | **57.0%** | **68.5%** |

### 2.1 三个读数

1. **投票几乎无效**：基座 48.0% → 47.0%（**−1 pp**），LoRA 55.0% → 57.0%（+2 pp）。
2. **连上界都很低**：基座 oracle@32 只有 **51.0%**——采样 32 次，
   只有 3 pp 的题"偶尔能蒙对"。说明**大部分错题它根本不会**，不是"会但不确定"。
3. **LoRA 的 oracle 高得多**：68.5% vs 投票 57.0%——
   说明 RL 之后模型对同一题能给出不同答案，**但正确答案不是多数派**。

### 2.2 成本

| | 每题耗时 | 相对 N=1 |
| --- | ---: | ---: |
| 基座 N=1 | 9.8 ms | 1× |
| 基座 N=32 | **314 ms** | **32×** |
| LoRA N=32 | 450 ms | 46× |

花 **32 倍推理算力**，换来 −1 pp。而昨天 RL 花 **20 分钟一次性训练**，换来 +13 pp，
推理成本不变。

---

## 3. 为什么投票没用：错误是系统性的

100 道题 × 16 采样，直接测量答案分布：

| 温度 | 每题不同答案数 | top-1 占比 | 16 次全错的题 | 投票准确率 | oracle@16 |
| --- | ---: | ---: | ---: | ---: | ---: |
| T=0.8, top_p=0.95 | **1.88** | **88%** | **43%** | 52.0% | 57.0% |
| T=1.2, top_p=1.0 | 2.62 | 82% | 35% | 51.0% | 65.0% |

两个关键数字：

- **top-1 占比 88%**：16 个采样里，同一个答案平均出现 14 次。
  模型的输出分布极度尖锐——它"确信"自己算的（错的）结果。
- **43% 的题 16 次全错**：这些题它不是"可能对"，是"根本不会"。

### 3.1 提高温度能增加多样性，但救不了准确率

把温度从 0.8 提到 1.2：

- 不同答案数 1.88 → **2.62**（多样性确实上来了）
- oracle 57% → **65%**（正确答案出现的机会变多）
- **但投票准确率 52% → 51%（没变）**

因为多出来的正确答案仍然是**少数派**，被多数错误答案淹没。

> 这就是 self-consistency 的适用边界：它假设"错误是随机的、正确答案是吸引子"。
> 对算术这种**确定性计算**，模型一旦形成错误模式，错误本身就是吸引子。

---

## 4. 什么时候投票有用，什么时候没用

| 任务类型 | 投票效果 | 原因 |
| --- | --- | --- |
| 算术 / 精确计算 | ❌ 无效 | 错误系统性，且模型"自信地错" |
| 多选题 / 分类 | ✅ 有效 | 错误接近随机，正确答案概率最高 |
| 开放式推理（有 CoT） | ⚠️ 视情况 | 需要采样路径足够多样 |
| RAG 事实抽取 | ❌ 基本无效 | 抄错的那个数字会被反复抄错 |

**判据**：先看 `oracle@N`。如果 oracle 比 N=1 高很多（比如 +15 pp 以上），
说明模型"会但不确定"，投票值得做；如果 oracle 几乎不涨（本例 +3 pp），
说明是能力问题，投票纯属浪费算力。

## 5. 和 RL 的对比（同一任务）

| | 测试时扩展（N=32 投票） | 训练时扩展（GRPO 300 步） |
| --- | ---: | ---: |
| 准确率变化 | **−1 pp** | **+13 pp** |
| 成本 | 每题 32× 推理（314 ms） | 一次性 20 分钟，推理不变 |
| 能否叠加 | — | 可以（RL 后再投票仍无增益） |
| 适用条件 | 错误随机 | 有可验证奖励 + 足够容量 |

### 5.1 一个反直觉的点

RL 之后 `oracle@32` 从 51% 涨到 68.5%，但投票只到 57%。
说明 RL **提高了"会不会"**（有些题原来一次都对不了，现在偶尔能对），
但**没有让正确答案成为众数**。

> 如果目标是"稳定答对"，RL 之后可能还需要一步**拒绝采样微调**（只拿对的那条继续训），
> 才能把"偶尔对"变成"经常对"。这是下一步可以验证的。

## 7. 结论

1. **投票不是免费的午餐**：先测 `oracle@N`，不涨就别投；
2. **算术类任务的错误是系统性的**（top-1 占比 88%），多数投票只会放大错误；
3. **43% 的题采样 16 次一次都不对**——这不是"运气不好"，是"不会"；
4. **同样的算力，训练（RL）比推理（投票）划算得多**：
   +13 pp vs −1 pp，且训练成本只付一次；
5. **RL 提升的是"能力"，不是"确定性"**：oracle 涨了 17 pp，但正确答案仍未成为众数。
