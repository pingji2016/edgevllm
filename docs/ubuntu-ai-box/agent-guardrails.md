# Agent 护栏：能改流程，改不了能力

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-27
> 承接 `mini-agent.md`：无护栏 65%（13/20）

上一轮结论留了个建议："加流程约束（先读后答、每步校验、限制步数）"。
这一轮**把它实现并实测**，回答：

> **65% 是小模型的天花板，还是 prompt/工程没写好的锅？**

答案：**是天花板。**

> 四道护栏全部触发（拒绝提前作答 2 次、路径纠错 7 次），
> 准确率仍是 **13/20 = 65%**，一分没涨。

---

## 1. 四道护栏

| 护栏 | 实现 | 拦什么 |
| --- | --- | --- |
| **路径白名单** | 非法路径返回"文件不存在 + 当前可用文件列表" | `workzone/words.txt` 这类幻觉 |
| **强制先读后答** | 任务里点名的文件没读过 → 拒绝 `finish`，提示先读 | 不读文件就编答案 |
| **单 JSON 校验** | 用 `raw_decode` 只取第一个对象；解析失败提示重试 | 一次吐两个 JSON |
| **重复读缓存** | 同一文件第二次读直接返回缓存 | 死循环重读 |

---

## 2. 结果

| 版本 | 成功 | 步数 |
| --- | ---: | --- |
| 无护栏（修正判据后） | **13/20 = 65%** | 2–6 |
| **四道护栏全开** | **13/20 = 65%** | 2–6 |

**逐题对比：完全一样。** 失败的还是那 7 条。

### 2.1 护栏触发统计（证明它真的在工作）

| 护栏 | 触发次数 |
| --- | ---: |
| 拒绝提前作答（强制先读） | **2** |
| 路径不存在 → 给出可用文件 | **7** |
| 非法 JSON 重试 | 0 |
| 重复读缓存命中 | 0 |

> 不是"护栏没生效"，而是**生效了也没用**。

---

## 3. 为什么没用

### 3.1 被拒绝后，它读了文件，但还是答错

典型是「log.txt 里 ERROR 出现了几次」：

1. 模型直接 `finish(answer="0")`；
2. 护栏拒绝："你还没读 log.txt"；
3. 模型读了，然后……**还是答 0**（它不会数）。

护栏能强迫它"看"，但看懂了没有是另一回事。

### 3.2 路径纠错给了正确答案，它还是不采纳

「words.txt 最长的单词」：

1. 模型读 `workzone/words.txt` → 护栏返回"不存在，可用文件有 words.txt…"；
2. 模型**又读了一次 `workzone/words.txt`**（7 次路径错误里有 6 次来自这一题）。

**它能看到正确路径，但不会改自己的计划。**

### 3.3 剩下的失败根本不是流程问题

| 失败 | 性质 |
| --- | --- |
| 求平均写成 `10+20+30/3` | 数学表达 |
| 比较文件名长度 | 推理 |
| 「bge-m3 的 R@1」答 42% | 题目歧义 |

护栏对这三类**无能为力**。

---

## 4. 那什么能提升

按性价比排序：

| 手段 | 预期 | 理由 |
| --- | --- | --- |
| **加更细的工具**（`count_matches`、`max_by`、`mean`） | **高** | 把"数 ERROR"变成工具调用，绕开模型算术 |
| **换更大模型**（7B+） | 高 | 差的是推理，不是格式 |
| 让模型写"计划-执行-检查"三段 | 中 | 需要模型自己有自检能力 |
| **继续加护栏** | **≈ 0** | 本轮已证明 |
| 换更强的工具调用框架 | 低 | 单轮选择已经 98% |

> 一句话：**护栏解决"不按流程走"，解决不了"走了流程还是错"。**

## 6. 结论

1. **护栏四道全部触发**（2 次拒绝作答、7 次路径纠错），准确率仍是 65%；
2. **65% 是 1.7B 在这个任务形态下的上限**，不是 prompt 工程问题；
3. **护栏只能约束流程，不能补推理**——拒绝后它会去读，但读完还是算错；
4. **正确的下一步是"给工具"而不是"给规则"**：
   把计数、求均值、比较这类操作做成工具，别指望模型自己算。
