# RFT 为什么几乎无效：正确样本的梯度本来就接近 0

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-26
> 承接 `test-time-scaling.md`：oracle@32 有 68.5%，多数投票只有 57%

上一轮留了一个猜想：

> RL 之后 oracle 涨到 68.5%，但多数投票只有 57%——
> **用"只保留答对的样本"继续 SFT（RFT / 拒绝采样微调），能不能把"偶尔对"变成"经常对"？**

结论：**几乎不能。**

> 训练 loss 一路掉到 **0.0000**，准确率只涨 **2 pp**（还在批处理噪声内），
> 而且**多样性反而下降**（oracle 56.0% → 54.5%）。

---

## 1. 方法

| 步骤 | 设置 |
| --- | --- |
| 采样 | 基座在 **2000 道训练题**上每题采样 16 个（T=0.8），共 32,000 次 |
| 筛选 | 只保留答案正确的样本 |
| 保留量 | 3,976 条（有正确样本的题占 57.1%） |
| 训练 | LoRA r=16（0.85% 参数），只对答案部分算 loss，2 epoch |
| 速度 | **0.19 s/步**，共 3,976 步（约 13 分钟） |
| 评测 | 固定 200 题（seed 999），贪心 |

---

## 2. 结果

### 2.1 准确率

| 模型 | 精确 | 误差<1% |
| --- | ---: | ---: |
| 基座 | 50.5% | 86.5% |
| **RFT** | **52.5%** | 89.5% |
| （对照）**GRPO 300 步** | **60.0%** | 96.0% |

**RFT 只拿到 +2 pp，GRPO 是 +13 pp。**

### 2.2 但先看一个测量问题

同一组 200 题、同一个基座、同样是贪心解码：

| 实验 | 基座准确率 |
| --- | ---: |
| GRPO 那轮（逐条解码，batch=1） | 47.0% |
| RFT 这轮（批量解码，batch=16） | **50.5%** |

**同一模型同一题集，差了 3.5 pp。** 原因是批量解码时 padding 与 kernel 选择不同，
bf16 的数值路径不完全一致。

> 所以 RFT 的 +2 pp **落在噪声里**，不能算有效提升。
> 这也是一个应该记住的教训：**对比实验必须用同一种解码方式**。

### 2.3 多样性反而下降

| 模型 | N=1 | N=16 投票 | oracle@16 |
| --- | ---: | ---: | ---: |
| 基座 | 52.5% | 52.5% | **56.0%** |
| RFT | 53.0% | 52.5% | **54.5%** |

RFT 之后 **oracle 反而掉了 1.5 pp**——它把原本"偶尔能对"的那部分多样性磨掉了，
却没有把准确率提上去。

---

## 3. 为什么：loss = 0 暴露了原因

训练日志：

```
step 2750/3976 | loss 0.0000
step 3000/3976 | loss 0.0000
step 3950/3976 | loss 0.0000
```

**loss 几乎为 0，说明模型对训练样本的预测概率已经接近 1。**

数学上很直接。交叉熵对某个 token 的梯度是：

```
∂L/∂logit = p − 1   （正确 token 处）
```

如果模型对"正确样本"本来就给 `p ≈ 1`，梯度就 `≈ 0`。

而 RFT 只训练**模型自己生成的、且做对了**的样本——这些样本恰恰是
**模型最确信的那部分**。训练它们等于**复习已经会做的题**。

### 3.1 决定边界的是错题，而 RFT 不碰错题

模型的准确率由"会/不会"的**边界**决定，边界由**错题**定义。
RFT 的筛选规则天然把错题全部丢弃，于是：

- 对的部分：`p` 已经从 0.99 推到 0.999（对准确率无影响）
- 错的部分：完全没被训练（边界不动）

**准确率当然不动。**

### 3.2 GRPO 做了什么不同的事

| | RFT | GRPO |
| --- | --- | --- |
| 用到的样本 | 只留对的 | 对的 + 错的都留 |
| 信号 | 绝对概率（推高正确） | **相对优势**（推高正确、**压低错误**） |
| 对错题的作用 | 无 | **直接压低** |
| 实测 | +2 pp（噪声内） | **+13 pp** |

GRPO 的优势函数 `(r − mean)/std` 同时作用在两个方向：
它不只是"多写对的"，而是"少写错的"。

---

## 4. RFT 在什么情况下才有用

RFT / STaR 类方法并非无效，只是**有前提**：

| 条件 | 说明 |
| --- | --- |
| **正确样本概率很低** | 模型"偶尔蒙对"（p≈0.01–0.1），此时梯度才大 |
| **样本来自 teacher / 更强模型** | 即 off-policy 蒸馏，不是自己复习 |
| **任务有推理链** | 正确的**过程**比正确的**结果**信息量大 |

本例三条都不满足：

- 正确率 50%，正确样本的 `p` 已经很高；
- 样本全部来自自己；
- 只有结果，没有过程（`<answer>` 一个数字）。

> 换句话说：**RFT 擅长"把不会的学会"，不擅长"把会的做稳"。**
> 而这里的问题是后者。

## 5. 一张决策表

| 现状 | 该用什么 |
| --- | --- |
| 准确率 0–5%，模型基本不会 | 先 SFT（有标注/teacher 数据），RL 会塌缩 |
| 准确率 20–50%，对错混杂 | **GRPO / RLVR**（需要在错题上给负信号） |
| 准确率 50–80%，想更稳 | GRPO，或加过程奖励 |
| 准确率 80%+，只差最后一位 | 优先考虑解码策略/工具调用，别训了 |

## 7. 结论

1. **RFT 在这里几乎无效**（+2 pp，落在 3.5 pp 的批处理噪声内），GRPO 是 +13 pp；
2. **原因写在 loss 里**：正确样本 `p≈1`，梯度 `p−1≈0`，训练等于复习；
3. **决定准确率边界的是错题，RFT 把错题全扔了**；
4. **RFT 的适用条件是"正确样本概率低"**（模型刚够得着）或"样本来自 teacher"；
5. **附带一个测量教训**：批量解码与逐条解码在同一题集上差 3.5 pp，
   **对比实验必须固定解码方式**。
