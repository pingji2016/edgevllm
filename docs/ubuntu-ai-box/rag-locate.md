# 定位式 RAG：让模型只指位置，程序去抄写

> 机器 `pingji-MS-7B89` · RTX 5060 Ti 16 GB · 2026-11-25
> 承接 `rag-over-docs.md`（纯向量 R@1 42%、加 reranker 58%、端到端 839 ms）

上一轮留下的最大问题是：**检索对了，模型也会抄错数字**
（385.9 vs 221.8、3.68× vs 1.29×、1 小时 vs 676 ms）。

这一轮的假设很朴素：

> **如果数字由程序从原文里取，模型只负责"指出哪一句"，抄写错误就消失了。**

结论：**这个方向对了一半**——定位确实能免掉抄写误差、还能提速 36 倍，
但它撞上了另一个我们没预料到的墙：**markdown 表格**。

---

## 1. 第一版：让模型输出「段落号 + 原句」

提示词强制两行格式：

```
段落: <编号 1-3>
原句: <从该段资料中原样抄出能回答问题的句子>
```

### 结果：**0/12**

模型**完全无视格式**，直接把它当普通问答：

| 问题 | 模型实际输出 |
| --- | --- |
| CUDA Graph 提升多少 | `CUDA Graph 相比 eager 在单流下提升 84%。` |
| Kokoro 在 K3 的 RTF | `Kokoro在K3上运行的实时率（RTF）为0.49。` |
| Q4_K_M 的 decode 速度 | `Q4_K_M 的 decode 速度是 385.9 tok/s。` |
| minimind 预训练时长 | `2.8 小时` |

12 条里 **12 条**都忽略了「段落/原句」两行格式，解析率 0%，
模糊匹配率 0.00（因为 `原句:` 根本不存在，取到的是空串）。

> **这是 1.7B 小模型的典型缺陷：它理解"要抄句子"的意图，但不服从格式约束。**
> 和我们之前 constrained decoding 的实验正好互为印证——
> 那次也是"自然语言要求格式"0/4，换成 xgrammar 硬约束后 4/4。

## 2. 第二版：把定位变成单选题

改成一个模型最容易服从的输出：**只输出一个数字**。

```
下面每句有编号。请只输出包含问题答案的那一句的编号，
只输出一个阿拉伯数字，不要输出别的任何内容。

1. 边缘计算把推理放在离用户最近的地方。
2. ...
```

**12/12 都输出了数字** ✅ —— 格式服从性问题的解法是
**把输出空间压到最小**（一个 token 的整数）。

然后程序拿编号去取**原文那一句**，数字从原文里抽，模型碰不到。

### 结果：不如直接回答

| 方案 | 正确 | 延迟 |
| --- | ---: | ---: |
| A 直接回答（模型自己写数字） | **6/12（50%）** | 619 ms |
| B 单选定位（模型只选句号） | 4/12（33%） | 122 ms |
| C0 reranker 句子级（纯程序） | 5/12（42%） | 15 ms |

**定位反而不如直接回答。** 为什么？看它选中的"句子"：

```
# CUDA Graph 那题，B 选中：
"| vLLM 单流（CUDA Graph） | **112.3 tok/s** |"
```

**这是一行 markdown 表格。** 它脱离了表头，就不知道"112.3"对应的是哪一列、
是什么场景、和 84% 的提升是什么关系。

---

## 3. 根因：我们的文档里，数字几乎都在表格里

统计一下 77 篇文档的形态：

| 内容形态 | 占比（目测） | 定位难度 |
| --- | ---: | --- |
| markdown 表格行 | **大多数实测数字** | 单行语义不完整 |
| 列表项（`- ...`） | 中 | 依赖上一行 |
| 完整句子 | 少 | 可独立理解 |

一行表格 `| Q4_K_M | 221.8 | ... |` 本身**没有主语、没有场景**。
任何"按句子/按行"切分的方法都会**切掉它赖以成立的上下文**。

### 3.1 验证：给句子补上下文

对同一个句子池做三种增强，用**同一个 reranker** 定位：

| 方案 | 句子内容 | 正确 |
| --- | --- | ---: |
| C0 | 原始句子（裸表格行） | 4/12 |
| C1 | `[章节标题] 句子` | **5/12**（+1） |
| C2 | `[章节标题] 表头 \|\| 表格行` | **6/12**（+2） |

C2 的实际形态：

```
[CUDA Graph 与 CUDA stream] | 配置 | eager | graph | 提升 || | bf16 | 61.3 | 112.3 | +83.8% |
```

**加上章节标题 + 表头，定位准确率从 4/12 升到 6/12（+50% 相对），
和 1.7B 直接回答打平——但延迟只要 17 ms，是直接回答的 1/36。**

> 这是一个可以直接落地的结论：
> **做句子级检索时，必须给每个"单元"补上它的上下文头**（章节路径 + 表头），
> 否则切得越细，语义丢得越多。

## 4. 交叉验证路由：为什么没成功

想法很自然：**A 说的数字，如果能在"定位句"里逐字找到，就采信 A；否则返回定位句**。

### 结果：5/12（比 A 的 6/12 还差）

| 问题 | A 的答案 | 定位句 | 判定 | 为什么错 |
| --- | --- | --- | --- | --- |
| Kokoro 在 K3 的 RTF | "没有直接提到" | `[四、K3 实测] 实测耗时 225 vs 116 ms` | 采信 A | 两句都不含 RTF，规则却通过了 |
| vLLM 32 并发 tok/s | "1,789.8 tok/s" | `... 64 并发 3,357 tok/s ...` | 采信 A | 数字都在文档里，但**配置不同** |

**问题在于规则太松**：只要 A 的某个数字在定位句里出现过就算"核对通过"。
但文档里同一个指标有多个版本（eager/graph、32/64 并发、不同模型），
**"数字出现过"不等于"数字对得上"**。

> 教训：**交叉验证必须校验语义槽位，而不只是数字字面。**
> 比如要求"A 的数字 = 定位句里**与问题关键词同列**的数字"。

## 5. 汇总

| 方案 | 正确 | 延迟 | 答案可溯源 | 说明 |
| --- | ---: | ---: | :---: | --- |
| A 直接回答（1.7B） | **6/12** | 619 ms | ❌ | 会抄错，但会综合多句 |
| B 单选定位 | 4/12 | 122 ms | ✅ | 模型选句不可靠 |
| C0 句子定位（裸） | 4/12 | 15 ms | ✅ | 表格行脱离表头 |
| C1 + 章节标题 | 5/12 | 14 ms | ✅ | +1 |
| **C2 + 标题 + 表头** | **6/12** | **17 ms** | ✅ | 与 A 打平，**快 36×** |
| R 数字交叉验证 | 5/12 | ~630 ms | ⚠️ | 规则太松 |

### 5.1 失败的 6 题分三类

| 类型 | 题目 | 根因 |
| --- | --- | --- |
| **召回缺失**（4 题） | Kokoro-K3 RTF、KV cache 字节数、DeepSeek-OCR 单页、MiniCPM-o 编译错 | 正确文档不在 top-3（主题稀释 / 20+ 篇 K3 文档） |
| **语义干扰**（1 题） | CUDA Graph 提升多少 | 定位到 `"官方文档说通常提升 10–30%"` 这句"元讨论"，不是实测表格 |
| **题目歧义**（1 题） | vLLM 32 并发 tok/s | 文档里有 eager 1,789.8 / graph 3,020 / 本轮 4,409 多个正确答案 |

### 5.2 两个判据问题（不是模型的错，但必须记）

1. **Kokoro RTF**：模型答 `0.49`，我的关键词是 `0.48` —— 0.48–0.49 都对，
   **判据过严**；
2. **vLLM 32 并发**：这题本身没写清楚"哪种配置"，**题目有歧义**。

> 自动评测里，**判据错误会把"对"算成"错"**。上一轮的千分位逗号同理。

## 6. 落地建议：正确的"引用式 RAG"长什么样

经过这两轮，形态清楚了：

```
① 召回    向量 top-20（bge-small-zh）
② 重排    bge-reranker 交叉编码器 → top-3 块
③ 切单元  块内按"句子 / 表格行"切，
           每个单元前面拼上【章节路径 + 表头】   ← 本轮最关键的一步
④ 定位    reranker 对 (问题, 单元) 逐对打分 → 取最高分
⑤ 输出    直接返回该单元的**原文**（逐字），并附文件名 + 章节
```

要点：

- **能让 reranker 干的，不要交给 LLM**：定位是判别任务，交叉编码器比 1.7B 更准、更便宜（17 ms）；
- **LLM 只在需要"综合多句"时才上**（比如"对比两种配置的取舍"），
  且输出必须带引用编号，由程序回填原文；
- **答案永远是原文**，模型的角色从"复述者"降级为"指路人"——
  这样模型多小都不影响数字正确性。

### 6.1 为什么这条路线值得

| 维度 | LLM 直接回答 | 定位式 |
| --- | --- | --- |
| 延迟 | 619 ms | **17 ms** |
| 数字正确性 | 依赖模型的抄写能力（1.7B 明显不够） | **由构造保证**（取自原文） |
| 可审计 | 只能说"资料里写的" | **能给出文件名 + 章节 + 原文行** |
| 换模型 | 要重训/换更大的模型 | **不用换** |
| 局限 | — | 无法回答"需要跨多段推理"的问题 |

## 8. 三条结论

1. **小模型的格式服从性要靠"压缩输出空间"解决**：
   两行格式 0/12 服从 → 只输出一个数字 12/12 服从。
   和 constrained decoding（xgrammar 0/4→4/4）是同一个道理。
2. **表格行是最小的"不可独立语义单元"**：
   加章节标题 +1，再加表头 +2，定位从 4/12 到 6/12。
   **任何句子级检索都必须做上下文拼接。**
3. **定位式在 1/36 的延迟下追平 1.7B 直接回答，且答案逐字可溯源**；
   但它治不了召回缺失（4/12 的失败是检索的锅）——
   **检索质量仍是一切的上限。**
