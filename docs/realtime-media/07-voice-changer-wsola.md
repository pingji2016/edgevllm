# 自己写一个变调器：WSOLA + 重采样

[03-voice-pitch-and-formant.md](03-voice-pitch-and-formant.md) 讲了「音高 ≠ 音色」，
并用 `rubberband` 做了对照实验。这一篇不调库：**60 行 numpy，从零写一个「变调不变速」**，
然后在 RISC-V 板（SpacemiT K3）上量实时余量。

目标：给定半音数 `n`，输出音调 ×`2^(n/12)`，时长不变。

## 一、两步，不是一步

变调 = **时间拉伸** + **重采样**，两步缺一不可：

```
原始 x(t)              ── 时间拉伸 p 倍 ──►   y(t) 时长 ×p，音调不变
                                                     │
                                          ── 重采样 1/p ──►  z(t) 时长还原，音调 ×p
```

- 时间拉伸：把波形"拉长"但**每一段的频率成分不变**（WSOLA / PSOLA / 相位声码器都做这个）
- 重采样：按 `p` 的步长重新取点，等于用不同的采样率去播同一段波形
  → 频率 ×p，时长 ÷p

净效果：时长不变，音调 ×p。

### 只重采样会怎样

只做第二步（`--mode resample`），时长和音调是**耦合**的：

| 操作 | 时长 | 音调 | 等价于 |
| --- | --- | --- | --- |
| 重采样 1.25× | ÷1.25 | ×1.25（+3.9 半音） | 磁带快放 |
| 重采样 0.80× | ÷0.80 | ×0.80（−3.9 半音） | 磁带慢放 |

这就是老式磁带变速变调的原理。它**不是变声**，因为语速跟着变了 ——
用户听到的第一反应是"你怎么变快了"，而不是"你换了个嗓子"。

## 二、WSOLA 的关键那一行

时间拉伸最朴素的做法：每帧取 1024 点、加窗、按 256 点跳距叠加。跳距固定，输出就变长了
——**但接缝处相位对不上**，相邻两帧在重叠区互相抵消，听起来是每 256 点一次的「嗡」
（16 kHz 下 62.5 Hz 的周期性噪声）。

WSOLA 的补丁很朴素：**别按固定位置取帧，在 ±300 点范围内找一段"和上一帧的自然延续最像"的波形**。

```python
# prev_tail = 上一帧"如果继续往后放"会出现的波形（长度 768）
lo, hi = max(0, center - TOL), min(len(x) - FRAME, center + TOL)
seg  = x[lo : hi + len(prev_tail)]
corr = np.correlate(seg, prev_tail, mode="valid")   # ← 关键的一步
pos  = lo + int(np.argmax(corr))
```

这句话的意思是「找一段波形，让它的开头和你本来要接的地方最相似」，于是重叠区同相叠加，
接缝就听不出来了。代价是每帧一次互相关：`O(FRAME · (2·TOL + FRAME))`。

完整实现（[scripts/voice_changer_wsola.py](../scripts/voice_changer_wsola.py)）：

```python
def wsola(x, stretch):
    win = np.hanning(FRAME)
    ana_hop = SYN_HOP / stretch          # 分析跳距随拉伸倍数走
    out = np.zeros(int(len(x) * stretch) + 2 * FRAME)
    wsum = np.zeros_like(out)
    prev_tail = None
    for i in range(int(len(x) * stretch / SYN_HOP)):
        center = int(i * ana_hop)
        ...
        frame = x[pos:pos + FRAME] * win
        o = i * SYN_HOP
        out[o:o + FRAME] += frame
        wsum[o:o + FRAME] += win
        prev_tail = x[pos + SYN_HOP : pos + SYN_HOP + (FRAME - SYN_HOP)]
    return out[:int(len(x) * stretch)] / np.maximum(wsum, 1e-6)
```

两个参数值得记：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `FRAME` / `SYN_HOP` | 1024 / 256 | 75% 重叠。重叠越多接缝越平滑，代价是算力 ×4 |
| `TOL` | 300 点 | 搜索半径。约 2 个基音周期（16 kHz 下 100 Hz 男声是 160 点），够覆盖相位差 |

## 三、验证：用已知真值的信号，别用估计器去验估计器

先说结论再讲过程。

### 合成信号：精确命中

| 输入 | 操作 | 实测输出 | 理论值 |
| --- | --- | --- | --- |
| 200 Hz 正弦 | +6 半音 | **283.0 Hz** | 282.84 |
| 200 Hz 正弦 | −6 半音 | **141.0 Hz** | 141.42 |
| 200 Hz 正弦 | 重采样 1.25× | **250.0 Hz** | 250.00 |
| 120 Hz 锯齿 | +6 半音 | **170.0 Hz** | 169.71 |
| 120 Hz 锯齿 | −6 半音 | **84.0 Hz** | 84.85 |

锯齿波那一行是特意加的：它谐波丰富（像浊音），能顺带验证「谐波结构跟着基频一起搬家」，
而不只是单频点搬对了。

时长（10.34 s 的原声）：

| 模式 | 输出时长 | 预期 |
| --- | --- | --- |
| `pitch +6` | 10.38 s | 不变（多出的 0.04 s 是 WSOLA 的尾巴补零） |
| `pitch −6` | 10.43 s | 不变 |
| `tempo 1.25` | 8.33 s | ÷1.25 = 8.27 s |
| `resample 1.25` | 8.27 s | ÷1.25 = 8.27 s |

### 负结果：语音的 F0 估计器不可靠

一开始我想直接用「语音的基频中位数」来验：原声 235.3 Hz，+6 半音应该到 332.8 Hz。
结果测出来 **280.7 Hz**；而 `resample 1.25`（应该到 294.1 Hz）测出来**也是 280.7 Hz**。

两个不同操作的估计值撞在同一个数上，说明问题在估计器，不在算法：

- 自相关 / 倒谱在**谐波丰富 + 基频快速变化**的语音上会锁到谐波上（倍频 / 半频错误），
  取中位数并不能消除这种偏置；
- 逐帧比值一度出现 0.49 / 0.71 / 1.41 / 1.31 这种「跳跃」，正好是 1/2、1/√2、√2 的整数倍关系
  —— 典型的八度错误。

结论：**验证 DSP 要用已知真值的合成信号**。用估计器去验证另一个估计器，
最后只能得到"两个都不准"。

## 四、K3 实测

SpacemiT K3（RISC-V，单核），Python 3.14.4 + numpy 2.3.5，单线程，纯 numpy 没有 SIMD 特调。
10.34 s 语音，计时只圈住**算法本身**（预热一次，取 3 次最小值）：

| 采样率 | 操作 | 纯计算 | 实时倍数 |
| --- | --- | --- | --- |
| 16 kHz | +6 半音 | 225 ms | **46.0×** |
| 16 kHz | −6 半音 | 116 ms | 88.9× |
| 16 kHz | 语速 1.25× | 123 ms | 84.3× |
| 16 kHz | 重采样 1.25× | 7.7 ms | 1340× |
| 48 kHz | +6 半音 | 644 ms | 16.0× |

> 命令行直接跑一次的总墙钟是 564 ms（16 kHz / +6），多出来的 ~0.34 s 是
> Python 解释器启动 + `import numpy` 的成本，不是算法成本。做服务时进程常驻，这 0.34 s 应该摊掉。

两条规律，都能和实现对得上：

1. **耗时 ∝ 输出帧数。** +6 半音要拉伸 1.414 倍、−6 只要 0.707 倍，输出帧数正好差 2 倍，
   实测耗时 225 vs 116 ms（1.93×）—— 对得上。
2. **耗时 ∝ 采样点数。** 48 kHz 的采样点是 16 kHz 的 3 倍，实测 644 vs 225 ms（2.86×）。
   注意 `TOL` 是**绝对点数**（300 点），48 kHz 下只相当于 6.25 ms、约 0.6 个 100 Hz 周期，
   搜索窗偏窄 → 接缝对齐不如 16 kHz。好处是每采样点成本不变（只慢 3 倍），
   代价是宽带音频下要自己把 `TOL` 放大（然后接受更慢）。

## 五、和 rubberband 比

| | 这份实现 | `rubberband`（03 里用的） |
| --- | --- | --- |
| 算法 | WSOLA + 线性重采样 | 相位声码器 + 瞬态检测 |
| 共振峰 | **不保持**（升降调都会变音色） | `formant=preserved` 可保 |
| 代码量 | ~60 行 | 一个 C++ 库 |
| 音质 | 语音可用，音乐有明显金属感 | 接近商用 |

这份实现的价值在**可解释、可移植、零依赖**：60 行就能跑在 RISC-V 板、MCU、
浏览器 WASM 里，也方便看清"变声到底在算什么"。要产品级音质，还是用 rubberband 或
相位声码器 + 共振峰搬移（[03](03-voice-pitch-and-formant.md) 里有 15 行倒谱包络移植的配方）。

## 六、局限（都是欠账，不是秘密）

- **没有共振峰保持。** 升 6 半音会明显"花栗鼠"，降 6 半音会"唐老鸭"。
  原因是共振峰（音色）跟着基频一起被重采样搬走了。
- **没有实时化。** 这里是整段离线处理。实时要做：分块（比如 20 ms）→ 环形缓冲 →
  **跨块**的 WSOLA 对齐（`prev_tail` 要跨块传递），块边界还要交叉淡化。
  [05-realtime-engineering.md](05-realtime-engineering.md) 里的三种接缝伪影，这条链上一个都躲不掉。
- **降调没做抗混叠。** 重采样用线性插值，`p < 1`（降调）时是抽取，理论上会把高频折叠下来。
  16 kHz 语音 4 kHz 以上能量本来就少，实测没听出问题，但这是欠账，正确做法是先低通再抽取。
- **单声道 / 16 bit PCM / 整段读进内存。** 没有流式解码，也不处理立体声。
